# 센서 실측 & 캘리브레이션 절차

줄자 + 스마트폰 수평계만으로 하는 방법입니다. 순서대로 하시면 됩니다.

---

## 0. 준비 — 차량을 평평한 바닥에

측정 전 반드시:

- 바닥이 평평한 곳에 차량을 놓고 **타이어 공기압을 정상으로** 맞춥니다.
  1/5 스케일은 공기압만 빠져도 카메라 pitch가 1~2도 변합니다.
- 서스펜션이 있으면 **주행 시 하중 상태**로 만듭니다. (배터리·노트북 다 실은 상태)
- 차량 중심선을 바닥에 마스킹 테이프로 표시합니다. y 좌표의 기준선이 됩니다.

---

## 1. base_link 원점 정하기

**뒷차축 중심** = 좌우 뒷바퀴 중심을 잇는 선의 한가운데.

- 바닥에 이 점을 수직으로 내려 표시합니다 → 이게 `base_footprint`.
- `base_link`는 그 바로 위, 뒷바퀴 반지름만큼 높은 곳.
- 이후 모든 x/y/z는 **이 점 기준**입니다.

> 왜 뒷차축인가: Ackermann 조향의 자전거 모델에서 뒷차축 중심이 운동학
> 기준점이라, 경로추종(Pure Pursuit / Stanley) 수식이 그대로 맞아떨어집니다.

---

## 2. 위치(x, y, z) 실측

각 센서마다 **렌즈 앞면 중심**(LiDAR는 회전축 중심, GPS는 안테나 위상중심)까지:

| 축 | 재는 법 | 부호 |
|---|---|---|
| x | 뒷차축 수직면에서 센서까지 앞뒤 거리 | 앞이 + |
| y | 차량 중심선에서 좌우 거리 | **좌측이 +** |
| z | 뒷차축 높이에서 위아래 거리 | 위가 + |

**요령**: 센서에서 바닥으로 다림줄(실 + 너트)을 내려 바닥에 점을 찍고,
바닥에서 x·y를 재는 게 공중에서 직접 재는 것보다 훨씬 정확합니다.
z만 따로 바닥에서 센서까지 수직으로 재세요.

목표 정확도: **±5 mm**. 이 정도면 20 m 거리에서 각도 오차가 무시할 수준입니다.

---

## 3. 자세(roll, pitch, yaw) 실측

### 부호 규약 — 여기서 제일 많이 틀립니다

| 회전 | 축 | 양수 방향 | 이 차량에서 |
|---|---|---|---|
| roll | x (전방) | 오른쪽으로 기울면 + | 보통 0 |
| pitch | y (좌측) | **아래를 보면 +** | D455는 **음수**, C920은 **양수** |
| yaw | z (위) | **좌측을 보면 +** | 좌측 BRIO **양수**, 우측 BRIO **음수** |

### pitch / roll — 스마트폰 수평계

각도기보다 정확합니다 (0.2~0.5도).

1. 카메라 몸체의 **평평한 윗면**에 스마트폰을 올립니다.
2. 수평계 앱(iOS 기본 나침반의 수평계 탭 / Android `Bubble Level`)의 각도를 읽습니다.
3. 카메라 윗면이 광축과 평행하다는 전제입니다. 그렇지 않으면 렌즈 배럴에
   자를 대고 그 위에 폰을 올리세요.
4. **차량 자체가 기울어져 있으면 그 값을 빼야 합니다.** 먼저 차체 프레임
   윗면에 폰을 올려 기준값을 재고, 각 카메라 값에서 그 기준값을 뺍니다.

### yaw — 벽 표적법

각도기로 재기 제일 어려운 축이라 역산이 낫습니다.

1. 차량 중심선을 벽 쪽으로 향하게 놓고, 벽까지 거리 `L`을 잽니다.
2. 벽에서 **차량 중심선의 연장선상 지점**을 표시합니다 (원점 O).
3. 카메라 영상을 띄우고, **이미지 정중앙에 오는 벽 위의 지점** P를 찾아 표시합니다.
4. O와 P의 수평 거리 `d`를 재면:

```
yaw(도) = atan(d / L) × 180/π      # P가 O보다 왼쪽에 있으면 +
```

`L = 3 m`, `d = 15 cm`면 yaw ≈ 2.9도. 이 방법이면 **±0.5도**까지 나옵니다.

목표 정확도: **±2도**. 나머지는 4단계에서 잡습니다.

## 4. 내부 파라미터 (intrinsic)

### D455 — 할 필요 없습니다

공장 캘리브레이션 값이 `/cam_front/color/camera_info`로 그대로 나옵니다.
RGB-Depth 정합도 `align_depth:=true`면 드라이버가 처리합니다. 건드리지 마세요.

### BRIO ×2, C920 — 체커보드가 필요합니다

**오늘 프린터로 출력하면 됩니다.** 30분이면 끝나고, 안 하면 융합 정확도가
안 나옵니다. 왜곡계수(k1, k2)를 모르면 이미지 가장자리에서 수십 픽셀 틀립니다.

1. `calib.io/pages/camera-calibration-pattern-generator` 등에서 체커보드 PDF 생성
   (9×6 내부 코너, 사각형 25~30 mm). A3면 더 좋습니다.
2. **완전히 평평한 판**(폼보드, 아크릴, 하드보드)에 주름 없이 붙입니다.
   종이가 휘면 캘리브레이션이 통째로 틀어집니다.
3. 실행:

```bash
rosrun camera_calibration cameracalibrator.py \
    --size 8x5 --square 0.025 \
    image:=/usb_cam_left/image_raw camera:=/usb_cam_left
```
> `--size`는 **내부 코너 수**입니다. 9×6칸 보드면 `8x5`입니다.

4. 화면의 X / Y / Size / Skew 바가 전부 초록이 될 때까지 보드를 움직입니다.
   - 상하좌우 끝, 가까이/멀리, 기울여서 — 특히 **이미지 네 귀퉁이**를 꼭 채우세요.
   - 40~60장이면 충분합니다.
5. CALIBRATE → SAVE. `/tmp/calibrationdata.tar.gz`에 YAML이 나옵니다.
6. YAML을 `~/.ros/camera_info/<camera_name>.yaml`에 두면 `usb_cam`이 자동으로
   `camera_info` 토픽에 실어 줍니다.

**주의**: 캘리브레이션한 해상도로만 유효합니다. 1280×720으로 캘리했으면
운용도 1280×720으로 하세요. 해상도를 바꾸면 fx/fy/cx/cy를 비례 스케일해야 합니다.

### 체커보드를 오늘 못 구할 때 — 임시 근사값

**TF 트리 확인용으로만** 쓰세요. 융합에 쓰면 안 됩니다.
FOV에서 역산한 값이고 왜곡계수는 0으로 둡니다.

| 카메라 | 해상도 | fx = fy | cx | cy | 비고 |
|---|---|---|---|---|---|
| C920 | 1920×1080 | ≈ 1360 | 960 | 540 | DFOV 78° |
| C920 | 1280×720 | ≈ 907 | 640 | 360 | |
| BRIO (FOV 90°) | 1920×1080 | ≈ 1100 | 960 | 540 | |
| BRIO (FOV 78°) | 1920×1080 | ≈ 1360 | 960 | 540 | 기본값인 경우가 많음 |
| BRIO (FOV 65°) | 1920×1080 | ≈ 1730 | 960 | 540 | |

> **BRIO는 FOV가 65/78/90도로 전환됩니다.** Linux에서 현재 어느 값인지
> 확인하고 고정하세요. 모르고 쓰면 fx가 1.5배 틀립니다:
> ```bash
> v4l2-ctl -d /dev/cam_brio_left --list-ctrls | grep -i zoom
> ```

## 5. 외부 파라미터 미세보정 — `calib_refine.py`

실측만으로는 보통 3~8 cm / 2~4도 오차가 남습니다. LiDAR 점을 영상에 겹쳐
보면서 손으로 좁힙니다.

```bash
# 1) TF 트리 띄우기
roslaunch gigacha_bringup sensors.launch

# 2) LiDAR + 대상 카메라 켜기

# 3) 정합
python3 calib_refine.py \
    --camera-frame cam_left_optical_frame \
    --image /usb_cam_left/image_raw \
    --info  /usb_cam_left/camera_info \
    --cloud /ouster/points \
    --urdf-prefix left
```

**맞추기 좋은 장면** — 깊이가 급격히 변하는 수직/수평 경계:
- 방 모서리, 기둥, 문틀, 책상 모서리
- 라바콘을 3~10 m에 몇 개 흩어 놓기 (제일 좋습니다)
- ❌ 평평한 벽만 보이는 장면에서는 절대 못 맞춥니다

**조정 순서** (이 순서가 중요합니다):
1. `dyaw` — 좌우 정렬. 제일 크게 틀어져 있고 눈에 제일 잘 보입니다.
2. `dpitch` — 상하 정렬.
3. `droll` — 기울어짐. 화면 좌우 끝의 높이 차로 판단.
4. `dx/dy/dz` — 마지막. 각도가 맞은 뒤에야 의미가 있습니다.

> 각도 오차와 위치 오차는 가까운 물체에서만 구분됩니다. **3 m 이내 물체와
> 15 m 이상 물체를 동시에** 놓고 맞추면 둘을 분리할 수 있습니다.

`s`를 누르면 보정된 xacro property 6줄이 출력됩니다. URDF에 덮어쓰고
`sensors.launch`를 재시작하면 트랙바를 0으로 되돌려도 정합이 유지됩니다.
카메라 4대 각각 반복하세요.

## 6. 검증 체크리스트

```bash
# TF 트리에 끊긴 곳이 없는지
rosrun rqt_tf_tree rqt_tf_tree

# 실측값이 제대로 들어갔는지 (숫자를 직접 눈으로 확인)
rosrun tf tf_echo base_link cam_left_optical_frame
rosrun tf tf_echo base_link os_sensor
```

RViz에서:

- [ ] Fixed Frame = `base_link`, TF 디스플레이 켜기 → 모든 프레임이 **실제 장착
      위치와 눈으로 일치**하는가
- [ ] 각 `*_optical_frame`의 **파란 축(z)이 렌즈가 보는 방향**을 향하는가
      → 이게 틀리면 투영이 전부 무의미합니다
- [ ] PointCloud2를 `base_link` 기준으로 표시했을 때 **바닥 점들의 z가 −(뒷바퀴
      반지름)** 근처인가
      → 작년 코드가 `abs(z) < 0.2`로 지면을 거른 게 여기를 안 맞춰서 생긴 일입니다
- [ ] 차량 앞 3 m에 라바콘을 두고, LiDAR상 위치가 `x≈3.0, y≈0`인가

### 자주 나오는 증상 → 원인

| 증상 | 원인 |
|---|---|
| 오버레이가 좌우로 통째로 밀림 | `yaw` 부호 반대 |
| 상하로 통째로 밀림 | `pitch` 부호 반대 (아래=+ 규약 확인) |
| 가운데는 맞는데 가장자리가 벌어짐 | 왜곡계수 미적용 → 내부 캘리 필요 |
| 가까운 건 맞고 먼 건 틀림 | 각도 오차 |
| 먼 건 맞고 가까운 건 틀림 | 위치(translation) 오차 |
| 점이 이미지에 하나도 안 뜸 | `_link`와 `_optical_frame`을 바꿔 씀 |
| 뒤쪽 물체가 앞에 겹쳐 나옴 | z>0 필터 누락 (이 도구엔 들어 있음) |

```cpp
// 노드 시작 시 1회 (fixed joint라 시간에 무관)

    "cam_left_optical_frame",   // target
    cloud->header.frame_id,     // source
    ros::Time(0), ros::Duration(2.0));
```

```python
# Python
T = tf_buffer.lookup_transform("cam_left_optical_frame",
                               cloud.header.frame_id,
                               rospy.Time(0), rospy.Duration(2.0))
```
